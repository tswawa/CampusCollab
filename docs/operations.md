# 部署、使用与恢复

[English](operations.en.md) · [返回首页](../README.md)

2026-10-08。当前支持一套 SQLite 数据库和一个应用实例。不要让多个实例共享数据库。维护命令会获取独占数据库租约，应先停应用再运行。

租约使用 `<数据库路径>.lock/lease.sqlite` 的 SQLite 内核锁，在服务或维护命令运行期间持续持有；异常退出后由操作系统释放。`.lock` 目录和其中的文件会保留，不能通过删除、移动或替换它们来强行启动第二个实例。使用本机磁盘或单宿主本地数据卷；网络文件系统的锁语义不在当前验证范围内。

## 部署

先按首页安装 Node.js 24.13.1 或更新的 24.x、依赖并完成构建。`.env` 保留在部署方本地，不进入源码包或 Git。开发运行 `npm run dev`；编译后的单实例直接使用 Node 启动。

最低版本修正了 Windows 非 ASCII 路径的 `rmSync` 问题，见 [Node 官方发布记录](https://nodejs.org/en/blog/release/v24.13.1)。应用和维护入口会在打开数据库前拒绝不支持的运行版本；不要用放宽版本检查来替代升级。

1. 构建完成后，在 `.env` 中设置 `NODE_ENV=production`、真实 HTTPS `APP_ORIGIN` 和机构 `SCHOOL_TIMEZONE`。反向代理确实受控时才启用 `TRUST_PROXY`：设为该代理的地址（如 `127.0.0.1`、CIDR 网段或 `loopback`）；`true` 表示代理与应用在同一台主机。不接受跳数。
2. 设置独立持久路径 `DATABASE_PATH`、`UPLOAD_DIR`、`BACKUP_DIR`，保留 `API_HOST=127.0.0.1`；这些路径不要指向会被下一次构建清空的 `dist`。
3. 为新部署配置 `SETUP_TOKEN` 安装码；未配置时，应用仅在空库旁创建 `<数据库路径>.setup-token` 文件，部署负责人从主机取得并保密保存。安装码不会出现在状态接口、公开页面或日志中。
4. 运行 `npm start`。应用读取 `.env`，迁移数据库并提供编译后的前端；默认监听 `127.0.0.1:3000`，由反向代理终止 HTTPS。
5. 访问 `/api/health` 检查运行状态。首次打开网页会进入 `/setup`：选择中文或英文版本，填写机构、时区和首位管理员，并输入安装码。成功后自动进入管理终端且永久关闭初始化；已有业务记录的部署不能重新认领。中文初始化默认要求部门、年级和班级，英文初始化默认可选，管理员可按需要修改注册要求。

也可在首次启动前运行 `npm run admin:init` 进行可信主机上的交互初始化。Web 与 CLI 使用相同的一次性状态；两者不应重复执行。学校版本由管理员在系统设置中修改，所有成员刷新后统一更新，通知、邮件和导出遵循机构语言。原创内容不会自动翻译。

数据库与附件在上述配置路径，使用仅有必要目录权限的运行账号。`ALLOW_INSECURE_COOKIE=true` 只用于隔离的本地生产构建验收，不是公网设置。不要复制真实库到演示环境。仓库中的容器文件作为可选路径保留；按用户要求，本轮未执行 Docker 构建或验收，不能用本机结果声称该路径已复验。

## 使用

**负责人：** 选择模板，确认任务的报名、提交时间及机构时区。导入名单时使用文本编号，先查看映射、错误与重复项。系统不会按同名自动合并，也不会自动创建登录账号；绑定现有账号需要负责人明确选择。

在材料工作台查看每个人的状态。审核选择具体版本；补正说明问题项，重新提交保留历史。实际确认分钟与计划分钟分开。集体材料可以一次提交后逐人确认，不会自动把所有报名者当作到场。

先将每人处理为已确认、未完成、退出或拒绝等终态，再结项。下载 XLSX 可保留编号前导零；CSV 是标准文本交换格式，表格软件自动猜测类型时仍可能改变显示。ZIP 包含名单、已确认材料与文件校验清单。更正先重新开放，处理变化后生成新快照；旧包不会被静默覆盖。

**参与者：** 使用机构统一设置的语言版本。按材料要求提交并查看审核记录，补正时只修改相关内容。只能查看自己的个人材料和授权的公共材料。

**管理员：** 审批负责人和受控外部参与者，管理机构规则。交接负责人会收回旧负责人的管理权限；同时交接服务器、备份、域名和更新责任。

## 可选邮件

在“系统设置 → 通知设置”查看启用状态及发送记录，在“系统设置 → 数据管理”查看保存期限与已结项任务。邮件连接仍由部署负责人配置；界面不会伪造启用开关。内部记录编号不在常规列表展示，永久清理确认时才要求输入具体任务编号。

默认 `MAIL_ENABLED=false`，站内通知完整可用。启用邮件需要配置 `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`MAIL_FROM`；SMTP 服务器要求认证时，成对配置 `SMTP_USER`、`SMTP_PASSWORD`。非隐式 TLS 使用 STARTTLS；没有关闭证书验证的选项。

邮件只向当前有邮箱且获准的账号发送，发送前再次检查身份、邮箱和任务权限。管理页显示等待、发送中、SMTP 已接收或失败；SMTP 已接收不等于用户收到或已读。结果不明的中断不盲目自动重发，管理员核对后再重试。停服时可用 `npm run mail:send` 处理积压。勿向公开日志输出 SMTP 错误原文或凭据。

## 备份、升级与回退

1. 停止旧应用进程；前台运行时使用 Ctrl+C，并确认端口已不再监听。
2. 使用**旧版本编译程序**执行 `npm run db:backup`。备份命令不执行数据库迁移，包含数据库、附件及迁移清单。将备份复制到独立存储，另行安全保存部署配置及旧版本源码/构建产物。
3. 安装新版本依赖、构建，再用 `npm start` 启动；启动时迁移。检查账号、任务、材料、结果包与健康状态。
4. 若需回退，先停应用，再使用匹配版本执行 `npm run db:restore -- <备份目录>`，恢复整套数据库与附件，并切回对应旧版本构建产物。不要用旧代码直接打开已经成功升级的新库。

源码部署也按“旧程序停服备份 → 新程序构建与迁移 → 检查”执行。恢复会预检完整性，保留恢复前安全副本，并清空旧会话。备份目录和目标数据库/附件目录不能互相包含。`npm run files:cleanup` 只处理到期且无材料引用的临时文件。

`BACKUP_DIR`、`UPLOAD_DIR` 必须彼此独立，数据库不能位于这两个目录内。备份和恢复在创建目录、打开数据库前检查相同路径、父子关系及符号链接/路径别名；不要把备份放进附件树。恢复源可以是备份目录内的一份备份，但不能包含安全副本目录，也不能覆盖目标数据库或附件目录。

从旧版 PID 锁升级时，旧进程正常退出会自行删除 JSON 格式的 `<数据库路径>.lock` 文件。若异常退出留下旧文件，新版会明确拒绝启动，不根据当前命名空间内的 PID 猜测其已失效。部署负责人须先停止并核实所有使用该数据库的应用和运维命令，再备份并归档这个旧 JSON 文件；之后启动新版。新版 `.lock` 是目录，不能与旧 JSON 文件混淆。回退到仅支持旧 PID 锁的版本时，也须先停完全部进程，再随回退归档新版锁目录；任何运行实例存在时都不得移动锁。

## 保存与删除

管理员设置结项后的保存天数，默认 365 天。已结项任务可预览；保存期届满且没有阻碍才允许手动删除，不自动删除。预览后必须输入对应任务 ID 并确认；提交时重新核对预览版本。未结项、未到期、仍被其他任务引用的材料、发送中的邮件或无法归属的历史通知会阻止删除。

跨任务复用时，先清理已到期的引用任务；这只删除该任务的记录和自有文件，保留来源任务的版本与图片。所有引用解除且来源任务也到期后，才可清理来源任务。若存在多层引用，按最末引用方到来源的顺序处理；预览会重新核对仍存在的引用。

清理针对该任务的名单、材料版本、快照、通知及任务资料，账号保留；保留必要的最小删除审计。附件删除失败进入重试清单。服务器上的历史备份、下载到个人电脑的导出包不由这一按钮删除，部署方须另行执行备份到期策略，并在恢复后重新落实已批准删除要求。

## 范围与故障定位

通用结果包上限为 5000 人、50MB 材料，超出会明确拒绝。图片支持 JPEG/PNG/WebP，单图 10MB；没有任意文件上传或自动材料验真。相同图片的旧版本和跨任务引用不能被临时清理误删。

遇到冲突先刷新记录，保留当前输入并重新核对版本；不要反复点击审核。服务无法启动时优先看配置与数据库租约，不删除租约文件来强行并发。保留错误代码、应用版本和匿名复现步骤。公开发布前核对品牌资源、来源声明、CI、源码下载及学校模板的实际接受条件。
