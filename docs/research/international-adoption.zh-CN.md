# 海外高校采用研究与英文产品要求

**研究截止：2026-10-08（Asia/Taipei）。状态：研究与实施要求，不代表英文应用已经完成或通过部署验收。**

英文对照：[International adoption research](international-adoption.en.md)。总实施计划见 [PLAN.md](../../PLAN.md) 与 [PLAN.en.md](../../PLAN.en.md)。

## 1. 推荐方向与证据边界

推荐把产品做成面向高校内小型项目组的 **community engagement completion workspace（社区参与结项工作台）**：协调员先选定输出要求，参与者按清单提交，协调员处理缺件和补正，最后生成可核对的完成名单与材料包。产品运行边界仍是一所机构自行部署、一个小组织负责运营；不是付费就业市场、校级学分系统，也不自动签发官方成绩单。

本研究核查六所非中国高校、四个国家的公开一手资料：加拿大 University of Toronto，英国 King's College London、University of Warwick、University of Chester，美国 Sacred Heart University，澳大利亚 Adelaide University。另核查 GivePulse、Better Impact 的产品文档，以及 W3C、IANA、美国教育部和欧盟委员会的官方资料，共 16 个纳入证据的来源。

证据支持“报名、参与记录、人工确认、反思和成果输出”是实际存在的工作；不能证明这些学校有采购本项目的意愿，不能证明本项目比现有平台更省时，也不能估算全球市场规模。样本集中于英语环境，不代表所有海外高校。大学操作指南属于已公开的业务流程证据，供应商帮助文档属于产品能力证据，两者均不是本项目的采用或成效证据。

**不应把海外市场描述为蓝海。** GivePulse 和 Better Impact 已覆盖记录、确认与导出。值得投资的差异假设是：在一个具体结项场景里，把“还缺什么、谁需要修改、采用哪个确认版本、交付包能否直接核对”连成短流程，而不是继续增加通用功能。

最强反方是：已有成熟平台的组织，可能只需配置现有表单或报表就能满足需要；引入一个自托管系统反而增加账号、数据录入和维护。对此应限定目标为具有独立结项工作、明确维护者、且当前工具不能简洁完成该工作的小组织。不能凭开源、英文或“有 AI”反驳替换成本。

## 5. 英文产品与 i18n 要求

以下是拟实施要求，不是对当前功能的描述。第一版提供 `en` 与 `zh-CN` 的同等功能；英文面向海外组织，中文仍可用于同一部署内的参与者。仅支持这两种界面语言，不因此承诺其他语言、双向文字布局或所有地区政策。

| 项目 | 具体要求与验收关注点 |
|---|---|
| 英文定位 | 使用 “Coordinate community activities, resolve missing submissions, and prepare a reviewable completion pack.” 作为价值描述。不要把“接单”译成 paid gigs，也不暗示志愿活动必然授予学分。 |
| 角色 | 产品称 Coordinator、Participant、Administrator；Reviewer 是授权职责，可由协调员承担。第一版不必建立复杂组织权限引擎，但不能要求职员和社区志愿者注册成“学生”。 |
| 组织 | 单部署代表一所机构；下面使用可选的 unit/program/group。至少支持没有学院、年级和行政班级的组织。第一版不做无限层级组织建模。 |
| 身份 | 系统 user ID、登录凭据与可选 external ID 分离。external ID 为文本，保留前导零、连字符和大小写原值；允许空值，并明确唯一性范围。以管理员邀请/名册授权为初版入口候选；邮箱验证只证明邮箱控制，不能自动证明学生身份。 |
| 姓名 | 提供 Unicode display name；不强拆姓和名，不限制为中文姓名或最少两个字符。长姓名、单名、空格、连字符、重音符号均有验收样例；正式输出名称在模板中说明来源。 |
| 语言与时区 | 2026-10-08 产品决策更新：机构初始化选择中文或英文版本，之后由管理员统一管理，替代原个人语言偏好建议。机构语言与 IANA timezone 分开存储；修改语言不能改变截止时刻。机构为任务保存明确时区；界面展示活动当地时间与时区，不能从英文推定 America/New_York。 |
| 日期与 DST | 时间点按 UTC 保存并保留事件时区；纯日期字段保持 YYYY-MM-DD，不当作 UTC 午夜转日。使用本地化日期展示；对 DST 不存在时间拒绝并提示，对重复时间要求明确选择偏移。首版可以明确拒绝跨日活动，不能静默截断。 |
| 分钟与规则 | 保存整数分钟，避免浮点累计。计划时长、申报时数和确认时数分开；模板说明是否含准备、路程和休息。没有核验则显示 pending，不自动计零或计完成。 |
| 系统文案 | 页面、按钮、空态、验证、上传限制、邮件、站内通知、导出标题、管理员提示和无障碍名称都进入字典。第三方组件的日期与上传文案也需切换。 |
| 错误码 | API 返回稳定的机器错误码和参数，客户端按 locale 渲染；不得把中文错误字符串当业务分支条件。未知错误有双语 fallback 和支持用关联 ID，不向用户展示原始堆栈。 |
| 用户内容 | 活动标题、反思、反馈和附件名保留作者原文；不自动翻译、修改已确认材料或要求向 AI 服务发送数据。系统通知在接收者语言下生成，用户原文适当标明。 |
| 通知 | 浏览器即可完成全流程，无微信账号、微信 SDK 或小程序依赖。任务链接保持登录后的返回位置；邮件最少包含动作、截止时间/时区与链接，不附敏感材料。可查看发送失败并手动重发；演示若使用复制链接须明确标记未接通邮件。 |
| 导出 | 提供可选输出语言和固定版本模板；字段标识稳定、表头本地化。标明时区、生成时刻、模板版本、确认状态和生成者；文本 ID 不转数字，CSV/XLSX 防公式注入，附件重名和特殊字符有确定处理。 |
| 同功能 | 英文和中文均完成登录/授权、建活动、加入、提交、补正、审核、结项、导出、交接。切换语言保留草稿；不得只把宣传页或学生端做成英文。 |

时间处理使用 IANA 数据库作为依据；时区规则会变化，运维需要更新运行时的相关数据。[R02：IANA Time Zones](https://www.iana.org/time-zones)

## 6. 无障碍与采用评估

WCAG 2.2 AA 是工程目标，不是现有认证。第一版验收覆盖完整核心流程的键盘操作、可见焦点、表单标签和错误定位、状态播报、足够对比度、缩放重排和非颜色状态；上传与审核不能只能拖拽、拍照或用鼠标完成。自动扫描应与人工键盘和屏幕阅读器检查配合；完成一张检查表不能自动宣称全站符合标准。[R01](https://www.w3.org/TR/WCAG22/)

以下法律资料仅用于列出采用前的评估问题，不构成法律意见或合规承诺。机构需按自身活动、记录、所在地和合作关系判断适用要求，不能把美国、英国、加拿大、澳大利亚或整个欧洲视为同一法域。

- **FERPA 评估：** 涉及美国教育记录时，机构应确定记录性质、访问/更正请求流程与披露依据。若依赖外包 school official 例外，须评估机构控制、使用/再披露限制及本机构标准；安装一个自托管软件不自动满足这些条件。[R03](https://studentprivacy.ed.gov/faq/what-ferpa)、[R04](https://studentprivacy.ed.gov/faq/who-school-official-under-ferpa)
- **GDPR 评估：** 在适用时，确认处理目的与法律依据、必要字段、保留/删除安排、访问主体及处理者和跨境服务关系。工程默认收集最少数据、限制附件访问并记录导出；不能宣称“使用本项目即合规”。[R05](https://commission.europa.eu/law/law-topic/data-protection/information-business-and-organisations/principles-gdpr_en)
- **材料边界：** 第一模板不要求身份证件、健康信息或包含服务对象面孔的照片；反思可以纯文本。照片是材料，不是真实到场的保证。部署说明列出存储、备份、邮件服务和删除覆盖范围；核心流程不连接外部 AI。

## 7. 英文示例场景与验收

**示例名称：Campus Community Garden Volunteer Session。** 这是合成演示，不冒充任何所研究大学的活动或官方表格。组织为 Sustainability Office 下的 Community Garden Program；协调员是项目职员，参与者可含学生和职员。部署语言默认英文，某参与者使用中文；事件时区为 `Europe/London`。

固定模板 `community-service-session/v1` 要求：一段完成说明、一项简短反思、申报服务分钟数、协调员确认。照片默认可选。模板注明演示计时口径为实际服务时间，不含路程；这是示例规则，不冒充通行规则。正式宣称兼容某院校表格前，须取得该表格、版本和必填字段，并核查一次填充输出。

建议演示流程：

1. 协调员选择模板并发布两小时的活动，邀请八个虚构参与者；external ID 可空，姓名含单名、重音符号和中文。
2. 六人提交，协调员确认其中五人各 90 分钟；第六人的反思需补充，只针对该要求项发出 correction request；另外两人显示 missing submission。
3. 第六人看到明确修改原因，补交反思后，协调员确认 75 分钟。保留原提交、补正原因、再提交和审核版本。
4. 协调员结束本轮收集。活动结项并不强迫两名缺交者变成 completed；系统清楚区分“活动已结项”和“个人已完成”。
5. 预检后导出：六人完成名单、六人已采纳材料、八人核对清单、模板/快照信息。确认服务总量为 **525 分钟**，而非按八人或六人的两小时排期相乘。

建议交付包包含 `completion-register.xlsx`、`reconciliation.csv`、`evidence/participant-id/` 与 `manifest.json`。名单采用已确认数据；核对清单保留缺交者但不授予完成状态；附件按稳定参与者 ID 组织、显示姓名仅作辅助。版本和文件摘要用于核对导出完整性，不能证明参与或材料真实。

| 验收编号 | 必须观察到的结果 |
|---|---|
| INT-01 · 双语对等 | 同一数据集完整跑通英文与中文，所得参与状态、确认分钟、选用版本和导出行数一致。 |
| INT-02 · 身份包容 | 无班级的职员、空 external ID、`00017-A`、单名、重音姓名和中文姓名均能保留正确数据。 |
| INT-03 · 时区明确 | 改 locale 不改截止时刻；同一任务在机构时区显示一致。额外测试 DST 跳时与重复时间，不能静默选择错误时刻。 |
| INT-04 · 定向补正 | 第六人只看到自己的要求和反馈；修改反思不丢失其他材料；原版本和审核人可追溯。 |
| INT-05 · 结项核对 | 输出六条完成记录、八条核对记录、525 分钟；缺交者没有被计完成；导出对照所选快照可复核。 |
| INT-06 · 权限与交接 | 参与者不能读取他人附件或导出全体；更换协调员后旧权限被撤销、新人可继续审核且交接有记录。 |
| INT-07 · 触达与隐私 | 补正链接指向正确材料；邮件失败可见；不依赖微信、不将材料发送到 AI，邮件不含附件或敏感反思原文。 |
| INT-08 · 可操作性 | 键盘和屏幕阅读器完成报名、提交、补正、审核；状态不只靠颜色，英文长文案不截断关键操作。 |
| INT-09 · 效率验证 | 用相同合成任务比较表单+表格的结项操作，记录追问次数、手工复制字段数、主动操作时间和错配数；未测前不宣称节省百分比。 |

以上全部是未来验收要求，本研究未执行这些测试。前轮项目已有测试结果只适用于当时已测代码；它们不能证明新的英文、模板、历史和时数方案已实现。

## 8. 投资顺序、替代方向与停止条件

| 方向 | 价值 | 成本与限制 | 选择 |
|---|---|---|---|
| 公开源码与英文开发说明 | 有利于审阅、贡献和二次开发，启动成本较低。 | 协调员仍需技术支持，源码公开不等于可用产品。 | 作为发布基础，但不能替代完整体验。 |
| 单机构、面向小组织的自托管成品 | 可以控制数据和部署，围绕一个固定结项模板做短流程。 | 需要明确维护者、备份、账号支持和可升级交付；节省效果尚未测量。 | **推荐产品方向。** |
| 全校完整平台 | 可能覆盖统一身份、正式认定、学院体系与报表。 | 集成、采购、安全评估、长期支持和政策规则显著增加，直接面对成熟平台。 | 当前不投入。 |

**现在值得做：** 通用角色与简化身份、实际入口的完整双语、可靠时间规则、一个固定模板的缺件/补正/版本/结果包、受控交接、基本邮件触达与无障碍验收。选择“确认服务时数”作为首个海外模板时，同一迭代加入结构化分钟；若采用无时数材料模板，则不用先造完整 timesheet 系统。

**按场景决定：** 多次服务记录、外部组织核验人、机构名册自动同步、SSO、学校特定表格、课程关联和受限文件类型。基础文件名单导入已纳入总计划 T09；这里的自动同步指与机构身份系统连接。外部核验不能仅靠填一个邮箱就视为身份验证。优先采用机构已有流程，再决定是否接入。

**暂不做：** 自动学分发放、官方 CCR/HEAR 写回、工资与奖助金发放、自动排班、通用表单/规则引擎、多租户、原生 App、社交网络、AI 自动验收、人脸/定位真实性判定。

继续投入的依据应是可演示的工作减少：一个模板无需回到另一个表格补关键字段，缺件能直接定位到人和要求项，采用版本可重现，负责人交接后仍能继续办理。公开证据已足够支持这个有限产品方向；未知的是它对特定组织究竟节省多少时间与维护成本。

出现以下情况应收缩或停止对应扩展：必须依赖校级 SSO/官方认定才能产生第一份有用结果；结果包仍需重抄核心字段；现有平台配置即可完成同样流程；没有愿意承担部署维护的组织；真实场景需要的敏感材料超出本项目的治理能力。若模板不能减少协调员的机械整理，先改或弃模板，不以增加 AI、多语言数量或功能清单补救。

**本阶段交付边界：仅新增研究与计划文档；没有修改应用、发布 GitHub、部署服务或处理真实参与者数据。**
